# Type Juggling and Conversion Security

用于 PHP 弱比较、JSON 类型混淆、大整数精度、Unicode/字符窄化、重复解析和跨语言微服务。目标是证明不同输入在安全判断前被转换成同一值，或同一输入在不同层被解释成不同值。

## 1. 类型流

为可疑字段记录每一层的：原始字节 → URL/form/JSON 解码 → schema coercion → 语言运行时类型 → 规范化 → 哈希/签名 → 比较 → 数据库/文件/API 使用。

需要同时保留值与类型，例如：

```text
"0" (string) ≠ 0 (integer) ≠ false (boolean) ≠ null ≠ [] (array)
```

响应成功并不证明类型绕过；必须确认最终认证、对象、金额、路径或签名分支发生变化。

## 2. PHP 弱比较

高价值代码信号：安全值使用 `==`/`!=`、哈希结果未用 `hash_equals`、`strcmp` 返回值被弱比较、错误处理把类型异常折叠为 null、`json_decode` 产生布尔/数组后直接比较。

PHP 5/7/8 对非数字字符串、数组参数和 TypeError 的行为不同。应在与目标相同的大版本中用最小本地程序复现；不能因为一个经典样例在旧版本成立，就推断现网成立。

### Magic-hash 条件

只有双方结果都满足运行时的数字字符串规则，且代码使用弱比较时，类似科学计数法外形的摘要才可能被当作相同数值。需要证明：算法与输入可控、真实摘要满足条件、目标代码确实弱比较、最终安全分支通过。哈希外形本身不报告。

## 3. JSON 与跨语言差异

检查 schema 缺失或宽松时的：

- string/number/bool/null/array/object 替换；
- 大整数在 JavaScript、Java、Go、Python 或数据库之间的精度变化；
- `1`、`1.0`、指数形式、负零和超范围整数；
- 重复 JSON key 在网关和后端的 first/last 行为；
- 数字 ID 被序列化、签名后又以另一类型查询；
- 空值、缺失字段和显式 null 是否合并。

用自建对象 A/B 选择不会碰撞的基线，再构造仅类型不同的请求，观察最终对象与授权主体。

## 4. Unicode、字符窄化与 Ghost Bits

某些 Java/旧库或自定义代码会把高位 Unicode 字符窄化为 byte、只保留低位、错误折叠十六进制字符，或在不同层采用不同规范化。风险点包括：文件名、URL path、邮件头、转义序列、类名/关键字过滤和协议 framing。

验证方法：

1. 确认目标组件和转换函数，而非对所有入口投递字符表；
2. 在本地生成与目标危险 ASCII 字节映射到相同结果的候选字符；
3. 比较过滤前、转换后和最终 sink 的表示；
4. 使用无害标记证明路径、文件名、关键字或 header 被改变；
5. 只有跨越上传、路径、认证、注入或协议边界时才升级。

组件/CVE 名称只是路由线索，必须验证受影响版本、调用链和当前配置。

## 5. 数值和边界转换

金额、配额、时间戳、ID、bitmask 和长度字段需要检查溢出、截断、符号转换、浮点舍入及数据库类型回写。使用小规模测试值，禁止制造真实负余额、资损或资源耗尽。

## 6. 证据模板

- 正常输入的值、类型和结果；
- 单变量变体的原始表示；
- 每层转换结果或源码/错误证据；
- 最终安全分支与持久状态；
- 目标语言、库和版本；
- 影响及可回滚性。

防护通常包括严格 schema、显式类型检查、canonical encoding、范围校验、严格/常量时间比较，以及在同一规范化表示上完成签名和消费。
