# HTTP Request Smuggling / Desync

仅在存在前端代理、CDN、负载均衡或协议降级线索时使用。目标是证明解析边界差异，而不是用不稳定超时制造结论。

## 1. 架构前提

确认 HTTP/1.1 keep-alive、HTTP/2 降级、前端/后端组合、连接复用和 WAF/网关位置。若每个请求都建立独立后端连接，许多经典假设不成立。

## 2. 类型模型

- **CL.TE / TE.CL / TE.TE**：前后端对 Content-Length 和 Transfer-Encoding 优先级不同；
- **H2.CL / H2.TE**：HTTP/2 到 HTTP/1.1 转换产生边界差异；
- **CL.0 / 0.CL**：一端忽略 body 或长度；
- **pause-based desync**：一端在未完整 body 时转发；
- **header normalization**：模糊 TE、重复长度或换行在不同层被不同处理。

## 3. 验证阶梯

基线请求 → 单连接无害延迟差分 → 自己控制的下一请求错位 → 受保护测试路径或缓存的无害标记。每个结论需要重复对照并排除网络抖动、限流和后端慢响应。

## 4. 安全边界

不得捕获、改变或阻塞真实用户请求。避免在共享生产连接上使用可能毒化队列的 payload；风险不可控时记录 PENDING 并停止。

## 5. 报告门槛

单次 timeout、400、连接关闭或工具告警不是证据。需要证明前后端边界认识不同，并产生可复现的 ACL 绕过、缓存影响或自有后续请求错位。
