# SSRF Testing

用于 URL 抓取、Webhook、图片/文档预览、导入、代理、回调、PDF 转换和远程资源同步。

## 1. 确认服务端请求

使用自控 HTTP/DNS 端点，关联唯一随机标记并记录来源 IP、协议、方法、头、DNS 与 HTTP 时间。浏览器发出的请求、客户端预加载和第三方扫描器需要排除。

## 2. 边界模型

分别验证：

1. 允许的 scheme；
2. 主机校验使用原始字符串还是解析结果；
3. DNS 解析和连接是否发生在同一阶段；
4. 3xx 后是否重新校验；
5. IPv4/IPv6、端口、userinfo、大小写和尾点如何规范化；
6. 响应是否回显、只盲请求还是异步处理。

不要从命中一个 OOB 直接推断内网读取。

## 3. 低风险验证阶梯

自控端点 → 自控重定向 → 已知无敏感性的本机/内部健康端点 → 经确认范围内的云元数据只读标识 → 最小凭据能力验证。禁止端口大扫描和读取与证明无关的数据。

## 4. 云与内部服务

云元数据、Kubernetes service account、内部 Swagger、Redis/管理面都是后续假设，不是自动成立的影响。记录请求身份、网络位置以及得到的 token 的 audience、权限和有效期；只验证最小只读能力。

## 5. 常见误判

DNS 命中但无应用关联、URL 被安全扫描器抓取、客户端直接请求、代理返回固定模板、内部地址导致统一超时，均不足以报告。

## 6. 攻击链

将得到的服务名、URL、token、文档和对象 ID 回注 API、云资产、认证和数据联动。最终报告应是敏感内部能力、凭据滥用或跨网络边界的数据/动作，而不只是“存在 SSRF 请求”。
