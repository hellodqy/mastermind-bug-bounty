# File Upload Testing

把上传视为接收、校验、命名、存储、解析、转换和分发组成的管线，而不是只测试扩展名黑名单。

## 1. 生命周期清单

记录请求 Content-Type、文件字段、filename、服务端对象 key、返回 URL、存储域、访问控制、预览/转换任务、下载响应头和删除行为。确认每一阶段由哪个组件处理。

## 2. 关键差分

| 边界 | 比较项 | 有意义的结果 |
|---|---|---|
| 类型校验 | extension/MIME/magic bytes/实际解析器 | 校验器与解析器认识不同格式 |
| 文件名 | 分隔符、Unicode、截断、保留名 | 越过目录或覆盖测试对象 |
| 存储 | 随机 key、租户前缀、ACL | 跨用户读取或可预测覆盖 |
| 分发 | Content-Type、Disposition、独立域、CSP | 在受信任上下文被主动解释 |
| 转换 | 图片/文档/媒体/压缩包 | 解析器访问外部资源或本地路径 |
| 异步任务 | job/result/download ID | 跨用户获取转换结果 |

## 3. 安全样本

使用文本标记、无害多格式文件和自控外部资源；压缩包限制文件数、层级和展开后大小。不要上传持久化后门、恶意宏或会影响其他用户的内容。

## 4. 影响门槛

上传成功、允许双扩展名、对象存储公开但只含自有文件，都不是充分结论。需要证明至少一个边界：脚本执行上下文、服务端解析副作用、目录逃逸、覆盖、跨用户访问或敏感信息泄露。
