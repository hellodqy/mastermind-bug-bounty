# Injection Testing

以“输入进入哪个解释器”为起点，避免对所有参数使用统一 payload。先观察参数语义、技术栈、Content-Type 和错误形态，再选择低风险差分。

## 1. 解释器映射

| 信号 | 假设 | 首选证据 |
|---|---|---|
| 筛选、排序、报表、搜索 | SQL/NoSQL/ORM 表达式 | 错误、布尔对照、稳定时间差 |
| 模板、邮件、导出、预览 | SSTI/表达式语言 | 无害算术或字符串表达式 |
| ping、转换、构建、诊断 | 命令/参数注入 | 无害常量输出或受控延时 |
| LDAP/XPath/XML 查询 | 查询语言注入 | 真假条件与结果集差异 |
| header、日志、邮件头 | CRLF/header injection | 自控响应或测试消息中的新字段 |
| 重复参数、数组/对象 | HPP/类型混淆 | 不同解析层选择不同值 |

## 2. 基线与对照

至少保留：正常值、语法扰动、真条件、假条件。时间型证据要重复多次并包含相同长度的非延时对照；状态码变化必须排除 WAF、缓存、重试和通用错误页。

对 JSON、form、multipart、XML、query 分别建模，因为网关和应用可能采用不同解析器。重复参数要记录 first/last/array 行为。

## 3. 安全验证边界

- SQL/NoSQL：证明查询语义受控即可，不批量导出数据。
- SSTI/EL：优先无害算术；只有在明确授权和低风险条件下证明更深影响。
- 命令注入：使用无害标记或短延时，不建立持久连接、不修改文件。
- CRLF/邮件头：只在自控响应或测试收件箱验证。
- XSLT/解析器：优先本地转换差分或自控 OOB，不读取敏感文件。

## 4. 绕过只服务于已存在的假设

编码、大小写、注释、分隔符、Content-Type、重复参数和协议差分只有在基线显示解释器可达或过滤器差异时才使用。绕过 WAF 成功但没有进入解释器，不是漏洞。

## 5. 影响升级

语法控制应继续判断能否跨认证、读取敏感记录、修改授权状态、读取文件或执行代码。报告最终影响，不报告单独的报错、延时抖动或被拦截 payload。
