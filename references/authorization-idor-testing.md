# Authorization / IDOR Testing

用于对象级、字段级、函数级以及租户级授权。先建立主体—对象—动作矩阵，再选择最小伤害差分。

## 1. 对象图

记录对象的创建者、所有者、租户、父对象、可见角色和子资源。优先从列表、详情、附件、导出、历史记录和批量接口收集 ID；UUID 不是授权机制。

常见授权输入位置：

- path/query/body 中的 `id`、`userId`、`ownerId`、`tenantId`、`orgId`；
- JWT claim、cookie、header 或网关注入主体；
- GraphQL node/edge/global ID；
- 文件 key、分享 token、任务 ID、导出 ID；
- 嵌套资源中的父 ID 与子 ID。

## 2. 测试矩阵

| 维度 | 最小差分 | 必须证明 |
|---|---|---|
| 水平越权 | A 会话读取 B 的自建对象 | 返回内容确属 B |
| 垂直越权 | 普通角色调用测试管理动作 | 服务端执行了受限能力 |
| 跨租户 | 租户 A 主体引用租户 B 对象 | 租户隔离被跨越 |
| 字段级 | 请求/响应中加入受限字段 | 字段被接受、持久化或返回 |
| 函数级 | 更换方法、版本或等价路由 | 进入原本不可用的业务动作 |
| 关系级 | 更换 parent/child/owner | 服务端未重新验证关系 |

顺序：列表差分 → 详情 → 附件/导出 → 自建对象的添加与删除 → 可恢复字段修改。不得批量枚举或更改他人既有对象。

## 3. 容易漏掉的端点

同一对象的 `count`、`preview`、`download`、`export`、`history`、`search`、`batch`、`mobile`、旧 API 版本和异步任务结果，常由不同中间件授权。对一个已验证对象 ID，应沿关系图检查等价读取路径，而不是扩大随机 ID 扫描。

## 4. 证据要求

保留 A/B 正常请求、跨界请求和对象归属证据。屏蔽无关个人数据。HTTP 200、不同长度或存在性枚举只是线索；报告必须说明被跨越的主体/租户/角色边界和可复现结果。

## 5. 攻击链

对象读取后检查是否暴露下载 key、token、内部 ID 或下游操作；写越权后检查是否改变审批、角色、分享、任务执行或账号恢复，但只在测试对象上验证。
