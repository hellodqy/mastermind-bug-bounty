# Business Logic Testing

业务逻辑测试以状态机和服务端不变量为核心。客户端字段异常只有在服务端最终状态改变时才有意义。

## 1. 恢复状态机

对正常业务流记录：状态、允许动作、主体、对象、金额/数量/权益、前置票据、后续票据和最终账本。寻找创建—确认—支付—审批—履约—退款等步骤之间的服务端约束。

## 2. 不变量

- 金额、币种、数量和折扣必须与服务端商品/合同一致；
- 一次性权益、邀请、兑换和审批不能重放；
- 状态只能沿允许的边迁移；
- 中间票据应绑定用户、租户、对象、动作和有效期；
- 客户端角色或隐藏字段不能替代服务端授权；
- Web、移动端、旧 API 和后台渠道应保持相同业务约束。

## 3. 差分方向

每次改变一个变量：跳步、逆序、重复、使用旧票据、替换对象、改变客户端提供的派生字段、从另一渠道继续。并发问题交给 `race-condition-testing.md`，身份边界交给授权或账号接管资源。

## 4. 安全验证

仅使用测试账号、测试订单和可撤销权益。不得提现、转卖、消耗真实库存或影响第三方。异常金额或权益在服务端持久化即可作为证据，不需要完成真实结算。

## 5. 报告条件

必须描述被破坏的不变量、正常与异常状态转换、最终持久结果和可量化影响。按钮可见、前端价格变化、客户端校验缺失或被后续服务端拒绝都不构成漏洞。
