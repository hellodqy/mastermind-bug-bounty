# SCM and Build Artifact Exposure

用于站点直接暴露的版本控制元数据、构建产物、备份文件和目录索引。与公开代码搜索不同，重点是确认线上资产是否可恢复。

## 1. 候选面

- Git 元数据及对象；
- SVN working copy metadata；
- Mercurial/Bazaar 元数据；
- `.DS_Store`、编辑器交换文件和备份副本；
- sourcemap、构建 manifest、CI/CD 配置和打包清单；
- 目录索引、部署归档和旧配置。

## 2. 最小确认

先请求少数稳定元数据并区分真实内容、统一 200、WAF 模板和重定向。确认目标归属后，只恢复证明影响所需的最小文件，避免镜像整个仓库。

## 3. 优先分析

入口路由、API client、认证中间件、配置模板、部署脚本、历史差异和 secret 使用位置。凭据字符串、内网域名和源码本身先作为 lead；必须验证其与目标的归属及可用影响。

## 4. 安全边界

不公开、传播或提交恢复的第三方源码；证据中遮蔽密钥和个人数据。不要因为 `.git/HEAD` 可读就直接宣称源码或凭据泄露，需证明可恢复对象和实际敏感内容。

## 5. 回注

将 endpoint、参数、账号标识、token、签名方法和部署拓扑分别回注 JS/API、认证、云资产与 dependency CVE。最终报告聚焦可验证的数据、权限或凭据影响。
