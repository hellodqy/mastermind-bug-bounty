# AI Development Platform Attack Surfaces

用于云 IDE、AI 编程台、代码执行沙箱和带工作区/终端能力的 Agent 平台。关注身份层、控制层和执行层之间的授权关系。

## 1. 资产图

区分 Web UI、登录/会话、工作区 API、RPC/WebSocket、文件服务、终端/任务执行、插件/MCP、容器与云凭据。前端不可见不代表后端方法受保护。

## 2. 高价值假设

- UI 认证与 RPC/WS 认证不一致；
- workspace/project/thread ID 可跨用户替换；
- 文件、终端和任务方法只依赖可控客户端字段；
- 工具参数经过 shell、模板或路径解释器；
- 执行沙箱继承不必要的宿主、集群或云身份；
- 日志、错误或环境 API 暴露可复用凭据。

## 3. 安全验证

只使用自有工作区，先执行常量输出、读取自建文件或列出非敏感元数据。不得建立持久化、跨工作区读取、导出第三方代码或扩大云权限。

## 4. 证据与升级

方法枚举、登录页、错误形态和可见工具列表只是线索。报告需要证明未经授权的文件/任务/终端能力或跨工作区边界；环境变量只有在凭据被最小验证为可用时才升级。

## 5. 与 AI 安全的关系

Prompt injection 只有在能控制真实工具参数或越权数据流时才相关。传统 API、IDOR、认证、路径和命令注入仍应由对应 Skill 验证。
