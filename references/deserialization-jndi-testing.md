# Deserialization and JNDI Testing

用于原生对象流、JSON/XML/YAML 多态类型、消息队列、签名状态、Java 命名查找及框架对象绑定。

## 1. 识别格式与解析器

从 Content-Type、魔数、Base64 前缀、错误类名、类型字段和依赖版本识别 Java/.NET/PHP/Python/Ruby 对象流或 JSON/XML/YAML 库。确认输入是否在认证、签名验证或解密之前被解析。

## 2. 可达性分层

1. **格式可达**：合法与畸形输入产生解析器特有差分；
2. **类型可控**：用户能选择或影响实例化类型；
3. **行为可控**：setter、回调、查找、模板或文件操作被触发；
4. **影响可证**：出现受控 OOB、文件/数据访问或执行结果。

报告时不能把前一层直接描述成后一层。

## 3. 低风险探针

优先使用无害类型错误、已知不存在类、受控 DNS/HTTP 查找和常量行为差分。JNDI DNS 命中证明命名查找，但不自动证明远程类加载或 RCE；需要结合 JDK、协议、依赖与配置说明可达边界。

## 4. 常见信任错误

- 客户端签名存在但服务端先反序列化后验签；
- 允许任意类型名或宽泛 allowlist；
- 消息队列消费者信任生产者提供的类型头；
- JSON binding 把受限字段映射到危险 setter；
- 日志或表达式组件把用户数据二次解释。

## 5. 操作边界

不投递公开武器化 gadget、不修改文件、不建立反向连接。版本命中、堆栈或 OOB 线索需要与真实入口、解析顺序和最终影响共同进入 verifier。
