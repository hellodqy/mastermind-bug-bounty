# Subdomain Takeover Testing

用于作用域内子域指向第三方服务、子区 DNS 或外部邮件服务时的悬空绑定判断。核心门槛是“精确名称仍可被非所有者重新绑定”，而不是 CNAME 或错误页本身。

## 1. 证据链

按以下顺序记录：

1. 目标子域当前 DNS RRset 与 TTL；
2. 完整 CNAME/NS/MX 链，直到最终权威或服务商；
3. A/AAAA、HTTP、TLS 和供应商特征；
4. 资源是否不存在、仅未部署、私有、暂停或区域不匹配；
5. 服务商当前的名称占用和自定义域验证机制；
6. 该精确名称是否可由无关账号重新绑定；
7. 可信域关系带来的实际影响。

任何一环不确定时标记 PENDING，而不是确认接管。

## 2. DNS 类型

| 类型 | 要判断的核心问题 |
|---|---|
| CNAME | 最终 SaaS/云资源是否已释放且名称可重新声明 |
| 子区 NS | 委派的 nameserver 所属域或托管区是否可由外部控制 |
| MX | 邮件租户/域验证是否真的可被重新认领，而非服务暂停 |
| A/AAAA | 地址是否可由任意租户重新分配；仅云 IP 不足以证明 |
| 二阶链 | 中间 CNAME 活跃不代表最终目标仍存在，需解析到底 |
| Wildcard | 随机标签解析只证明通配，不自动证明第三方资源可认领 |

## 3. 指纹不是结论

供应商错误页可能因私有资源、缺少 Host 绑定、部署暂停、区域或 TLS 配置产生。至少结合 DNS 指向、供应商文档/当前行为以及名称绑定验证。历史指纹表会过时，不应把字符串匹配作为唯一证据。

## 4. 非占用式验证

默认使用：DNS/HTTP/TLS 证据、服务商控制台在最终提交前的可用性提示、由目标所有者提供的测试资源、或供应商确认。未经明确授权，不真正创建、绑定、上传页面、签发证书或接收邮件。

若项目规则允许目标所有者配合验证，使用专用测试子域和无害标记，验证后立即解除绑定并保留时间线。

## 5. 影响评估

只报告已观察到的信任关系：

- 父域 cookie 的 Domain/作用域是否覆盖该子域；
- OAuth redirect URI 是否允许该精确域；
- CSP 是否信任该域且已有可利用注入链；
- 邮件、下载、品牌或脚本加载是否引用它；
- 子区 NS 是否允许控制更多记录和证书验证。

不要从“可信子域”直接推断会话窃取、OAuth token 或全域控制。

## 6. 修复与复测

先解除 DNS，再释放第三方资源；或先保留资源名称，再调整 DNS。启用供应商域验证、持续监控 CNAME/NS/MX 目标和证书透明度。复测应确认 DNS 不再悬空且原名称无法由第三方绑定。
