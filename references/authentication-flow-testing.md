# Authentication Flow Testing

用于登录、找回、验证码、MFA、刷新和账号绑定场景。目标不是枚举表单，而是确认每个认证材料绑定的主体、用途和生命周期。

## 1. 建立认证图

为正常流程记录：入口、前置会话、账号标识、挑战、票据、回调、最终会话。对每个材料标注：

- **subject**：属于哪个账号或匿名会话；
- **audience**：供哪个客户端、域名或接口使用；
- **purpose**：登录、重置、换绑还是二次认证；
- **lifetime / consumption**：有效期、是否一次性、使用后是否失效；
- **context**：设备、IP、state、nonce、redirect URI、待执行动作。

只有异常材料最终改变了服务端认定的登录主体、凭据或绑定关系，才进入 verifier。

## 2. 高价值假设

| 面 | 应验证的不变量 | 有意义的差分 |
|---|---|---|
| 密码找回 | 挑战必须绑定账号和一次重置动作 | A 的挑战不能重置 B；旧票据不能复用 |
| 验证码 | 绑定账号、用途、会话和有效期 | 登录码不能用于换绑；验证 A 后不能替换为 B |
| MFA | 二次认证必须绑定已完成的一次登录 | 不能跳过步骤、重放状态或改 accountId |
| Refresh Token | 绑定客户端、主体和 token family | 不能换主体/受众；轮换后旧 token 失效 |
| 换绑 | 必须验证正确一侧并确认目标账号 | 攻击者验证材料不能应用于受害者标识 |
| 邀请/开通 | 邀请必须绑定租户、角色和收件人 | 不能改 tenant/role/recipient 获得更高身份 |
| 联合登录 | 外部 subject 必须稳定映射本地账号 | 不能只信 email/openId 等可替换字段 |

## 3. 差分方法

准备两个自有账号 A/B。先完成一次正常流，随后每次只交换一个元素：账号标识、challenge、ticket、cookie、state、客户端或步骤顺序。比较最终 `userId/tenantId/role`，不能只看“操作成功”。

安全顺序：只读身份确认 → 创建可回滚测试绑定 → 立即恢复。禁止登出、吊销用户现有令牌、锁定账号或改动非测试用户。

## 4. 会话与错误处理

检查登录前后是否轮换 session、敏感动作后是否提升 assurance level、旧票据是否因错误分支继续有效。错误回包中的 token、签名串或内部对象只是线索；必须验证其用途和实际边界。

## 5. 与其他方向的连接

- OAuth/OIDC/SAML 细节转到 `oauth-oidc-saml-testing.md`。
- JWT 结构与签名转到 `jwt-analysis.md`。

- 最终会话必须回注管理、导出、配置和对象接口验证实际权限。

## 6. 拒绝条件

仅有账号枚举、缺少客户端限速、可解码票据、错误信息、未证明可用的 token，均不足以报告账号接管。
