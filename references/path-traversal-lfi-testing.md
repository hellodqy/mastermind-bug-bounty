# Path Traversal and LFI Testing

用于下载、预览、模板、日志、语言包、图片、导入导出和压缩包处理中的路径规范化差异。

## 1. 路径处理链

画出：URL 解码 → 网关/路由规范化 → 应用拼接 → 库函数清理 → 文件系统解析。分别记录根目录、允许扩展、软链接行为和操作系统分隔符。

## 2. 假设类别

- 相对路径逃逸；
- 绝对路径被接受；
- 单/双重编码导致不同层看到不同路径；
- Windows/Unix 分隔符或盘符差异；
- 路由 path parameter 与 query 参数解析不同；
- 扩展名追加、截断或空字节差异；
- 归档条目造成 Zip Slip；
- 下载对象 key 绕过租户前缀。

不要机械遍历 payload；根据已观察到的解码次数、平台和错误形态选择最小变体。

## 3. 安全证明

优先读取应用自带的非敏感公开文件或自建标记文件。若只能用系统文件确认，选择不含秘密且内容稳定的标识文件，并停止继续枚举。写入只在隔离测试目录和自建文件上验证。

## 4. 证据门槛

错误中出现绝对路径只是信息泄露；统一 200 页面不是读取。证据需要显示返回内容确来自预期根目录之外，或归档条目实际写入测试根之外。

## 5. 链路

读取配置、源码或 token 后，只做最小有效性验证并回注认证/API。模板包含、日志包含或上传组合需要分别证明可达性，不能从任意读取直接宣称代码执行。
